# 米拉奇战记 · jks重置版

> 这是我为女朋友 **momosaysay** 制作的游戏。

## 游戏玩法

《米拉奇战记 · jks重置版》是一款横向战线策略对战游戏。开战前选择地图和交战阵营，之后通过招募互补兵种、管理金币与补给来推进战线，最终攻破敌方大本营获胜。支持单人对战 AI，也支持同一设备本地双人。

- **组建军团：** 14 种兵种分属前期、中期和后期，覆盖轻甲突袭、重甲防线、远程输出、范围清兵和后期英雄；利用重甲、远程、轻甲之间的克制关系调整阵容。
- **经营与出兵：** 每 20 秒结算递增收入并恢复 30 点补给。金币决定持续招募能力，补给和每方 30 名存活单位的战场上限限制军团规模；存活单位还能贡献额外收入。
- **争夺战线：** 前置长城封锁敌军并交替提供援军。攻破城墙后继续推进；摧毁敌方大本营结束战役。
- **主动技能：** 区域火炮轰炸交战地带；核弹能清除全场士兵并留下持续数回合的污染区。
- **变化战场：** 草地、沼泽和冰原各有地表环境，晴天、降雨或降雪会随战斗阶段变化。
- **多种游玩方式：** Windows 桌面版可离线运行；iPad 可通过 Safari 安装横屏网页应用，首次打开后支持离线游玩。

## V1.0–V1.2.1 地图与天气

开始战役时，单人或本地双人都会先选择一张地图，再选择双方阵营。地图在整局创建时锁定，不会在战斗中切换；地图负责地表、远景、装饰和小地图视觉，不改变兵种属性、经济、射程或胜负规则。当前包含米拉奇平原（草地）、灰雾沼泽（沼泽）和霜境冰原（冰原）。

天气以 70 秒为一个阶段自动轮换，并在战场左上角显示当前状态、切换时在画面中央提示。天气只有晴朗、小雨和小雪三种：草地与沼泽在晴朗和小雨之间轮换，冰原在晴朗和小雪之间轮换。V1.2 会用 3.5 秒渐变完成天气切换，晴朗天气增加低强度日照光束和太阳光晕，雨天分为远近两层雨幕并加入落地水花、固定积水和反射高光，雪天增加远近雪花层、风向斜线、雪堆起伏和底部积雪线；V1.2.1 将地面层和前景层分开绘制，积水与积雪使用固定世界坐标并在天气结束后缓慢消退，避免镜头移动时贴图漂移。草地雨天增加湿草高光，沼泽雨天增加更密的深色泥水与涟漪，冰原雪天增加风向雪线。天气不修改移动速度、攻击、射程、收入或补给，确保同一阶段的兵种平衡保持稳定。沼泽地表额外有静态泥潭和持续冒泡效果。

战线长度为 6200，前置城墙仍位于本方到敌方大本营的四分之一处，普通开局需要更长时间才能接触城墙。游戏开始后首轮先等待 8 秒，最后 5 秒在战场中央显示倒计时。独立镜头控制器只跟随实际交战中心，小幅阵形波动不会移动镜头，交战间隙保持当前位置；一方全灭时会立即将幸存军团整体置于画面中央，随后平滑跟随其推进。按 F 会立即重新锁定当前有效目标。

每 20 秒进入下一轮，收入随出兵轮数增加并将补给重置为 30。收入由大本营保障收入和存活部队收益组成：保障收入从 200 开始、每轮增加 50，最高 4000；每点存活补给额外产生 4 金币，部队收益最高为保障收入的一半，因此总收入最高 4000。阵亡单位从下一次结算起不再产生收益。前期兵价格为20–100，中期兵价格为100–1000，后期兵价格为1500–1800；弓箭手消耗3补给，每轮最多部署10个；忍者可以在开局直接购买，但需要2补给且只有90生命，主要用来闪现处理弓箭手。金币负责持续出兵，补给负责限制中后期单位的数量。每方最多同时拥有 30 个存活单位，满员时不会扣除金币或补给，出现空位后自动继续招募。兵种按敌人的轻甲 / 重甲类型造成不同伤害，再扣除护甲值。双方大本营拥有高防御和高伤害，会攻击附近敌军且不可再生；摧毁对方大本营即可获胜。六个阵营的大本营形制分别为王都石堡、海港灯塔、北境祖屋、熔岩锻炉、银月神殿和雾海白塔；前置长城统一不变。前置长城位于本方到敌方大本营的四分之一处，奇数回合从长城出兵、偶数回合从大本营出兵。长城防御和远程伤害较低，被摧毁后保持失守，只有本方反攻摧毁敌方长城时才会立即重建；长城万箭齐发会在城墙前方形成贯穿战场上下的三轮箭幕，覆盖整条纵向防御带。士兵死亡后会在原地倒地保留 2 秒，之后尸体从战场移除。

民兵是原“新兵”的正式名称，内部 id 保持不变以兼容旧存档和测试。区域火炮是独立技能，不占兵种名额；点击按钮消耗 2000 金币并自动轰炸当前交战区域，每 80 秒可用一次。轰炸区域固定为从战场顶部到底部、横向 1100 宽的条带，只随交战中心左右移动，不会随单位数量改变大小。约24枚导弹会以由慢到快的速度连续落下，士兵受到 5 次伤害，每次为该兵种应受总伤害的五分之一；单位中途死亡后不会继续承受后续波次。它只伤害条带内士兵，不会伤害城墙或大本营；敌方前期兵种可被秒杀，中期兵种会留下约16%生命，己方单位承受12%生命的少量误伤。前置长城还拥有自动万箭齐发：万箭射程内出现至少 4 个敌军，或长城受损过半且有至少 2 个敌军逼近时，自动连续射出 3 轮低伤害箭雨，冷却 100 秒。奇异博士是后期远程后排，射程 240，高于法师的 170；神秘兵种是中期随机召唤入口，固定价格 1000 金币、消耗 4 补给。每次招募神秘兵种都会从其他 13 种实际兵种中随机抽取一个出战，战斗属性以抽中的兵种为准，但仍按神秘兵种的价格、补给和存活收益结算。

本地双人为同一台电脑对战，不是网络联机。切出窗口或切到后台后游戏仍会继续运行；需要停战时使用空格或暂停按钮。

密集交战时，单位会按可见体型保持占位，并将攻击者分配到不同敌人周围。进入交战区域的近战单位会主动追击或攻击，不会因为前排拥挤而重叠、原地闲置。

远程兵会主动接近目标，但场上存在己方近战时，推进位置不会超过近战前线；已经越线的远程兵会边攻击边退回前线后方。敌人进入射程内侧时远程会尝试后撤并继续按自身攻击间隔开火，但远程移速低于重甲，重甲接近后可以追上。目标的小幅移动不会让它反复转向或中断攻击；轻甲和骑兵仍能更快贴近远程。

每个兵种的独特作用、弱点和当前数值见 [兵种定位与平衡](docs/BALANCE.md)。鼠标停留在兵种卡片上可查看特点提示。

## 修改源码

所有项目内容存放在 `D:\milaqi`。

```powershell
cd D:\milaqi
npm install
npm start
```

| 文件 | 用途 |
| --- | --- |
| `src/units.js` | 14 个兵种的数据、克制定位、基础规则、难度配置 |
| `src/engine.js` | 固定时间步战斗、自动招募、经济、AI、胜负 |
| `src/camera.js` | 镜头状态判断、交战锁定、幸存军团居中和平滑跟随 |
| `src/render.js` | 战场合成、六种大本营、长城、三种地形和小地图 |
| `src/weather-renderer.js` | V1.2.1 天气地面层、前景层、世界坐标积累和天气渐变 |
| `src/maps.js` | 地图目录、天气序列、天气状态和环境描述 |
| `src/sprites.js` | 原创角色视觉资产、关节动画、骑兵步态、材质与帧缓存 |
| `src/app.js` | 页面交互、快捷键、菜单、音量设置 |
| `src/audio.js` | 菜单 / 战斗场景音乐切换、战斗音效和天气环境音；曲目文件位于 `assets/audio/` |
| `src/style.css` | 面板、主菜单、响应式布局 |
| `desktop/main.cjs` | Windows 窗口、全屏、存储路径 |

兵种伤害、金币、补给和回合长度可直接修改 `src/units.js`。引擎不依赖界面或 Electron，能单独运行测试。

同一文件中的 `RANGED_TACTICS` 控制后排间距、有效掩护距离、敌人逼近的撤退阈值和大本营集结位置。双方阵营使用同一套后排逻辑；AI 在缺少近战兵时会优先补充掩护。

```powershell
npm test
npm run test:desktop
npm run build
node scripts/smoke.mjs --packaged
```

`dist` 是打包产物；修改源码之后需重新执行 `npm run build`。开发时 `npm start` 会直接加载源码。

## 文件位置

- 源码和依赖：`D:\milaqi\src`、`D:\milaqi\node_modules`。
- 下载缓存：`D:\milaqi\.cache`；npm 已通过项目 `.npmrc` 指向该路径。
- 构建 / 测试临时文件：`D:\milaqi\.tmp`。
- 开发版游戏设置和运行数据：`D:\milaqi\userdata`。
- 成品游戏设置和运行数据：exe 同目录的 `userdata` 与 `.tmp`。
- 测试报告与截图：`D:\milaqi\artifacts`。

游戏运行时禁止远程页面和 HTTP 请求；不连接账号、不依赖在线资源。Node.js 等机器上已有的工具继续使用原安装位置，本项目没有迁移或重新安装系统工具。



长城未被摧毁时，敌军不能从任何纵向位置穿过；前置援军从中央城门刷新。六种大本营分别使用石堡、灯塔、祖屋、锻炉、神殿和白塔的立体轮廓，颜色、旗帜和徽记随阵营变化；长城采用窄墙断面、外侧阴影和凸出的门楼，避免遮住交战单位。奇异博士发射金色旋转法阵，法师发射冰蓝晶弹，木乃伊挥甩裹尸布；骑兵突击、吸血鬼汲取、猩红裁决者的三式光刃技、至高领主劈斩、武僧棍环和忍者双刃弧光也有独立表现，攻击数值保持不变。
